# System Design — Learning Log

A collection of system design problems worked through in an **interview setting**.

## How we work
1. You give me a **problem statement** (e.g. "Design a URL shortener").
2. I produce a design document following `_TEMPLATE.md`, written the way I'd present it in an interview — reasoning out loud, stating assumptions, and calling out trade-offs.
3. If anything about scope or scale is ambiguous, **I'll ask you clarifying questions before diving in** rather than guessing.
4. Each problem gets its own file: `NN-<problem-name>.md` (e.g. `01-url-shortener.md`).

## Conventions
- `_TEMPLATE.md` — the standard outline every design follows.
- Files are numbered in the order we tackle them.
- Difficulty and key concepts are tagged at the bottom of each doc for quick review.
